{% comment %} Gets the rider hover-card out of the table it is trapped in. Two separate things bury it, and they need different fixes: 1. Clipping. daisyUI positions .dropdown-content with `position: absolute`, and nearly every table sits in an `overflow-x-auto` wrapper. CSS will not let one axis scroll while the other overflows, so those wrappers clip vertically too and the card is cut off for the last rows of a long table. 2. Stacking. Tables using `table-pin-col` make every first cell `position: sticky` with `z-index: 5` (responsive-tables.css). That cell is a stacking context, and the card lives inside one. Its own `z-index: 999` only competes *within* that cell, so the next row's cell -- same z-index, later in the DOM -- paints straight over it. No z-index on the card can fix this, and neither can `position: fixed`: fixed elements escape overflow, not stacking contexts. Only the top layer escapes both, so the card is promoted to a popover on hover and positioned against the viewport. The `popover` attribute is added by script rather than sitting in the markup: with JS off the card keeps daisyUI's CSS-only hover instead of becoming permanently invisible. Listeners are delegated from the document, so cards arriving in an HTMX swap need no re-init. Included once from base.html -- not from the partial, which renders per rider. {% endcomment %}
