{% load humanize accounts_tags %} {% comment %} The consolidated rider card, replacing the separate ZwiftPower, Zwift Racing and Racing Profile cards. One cached RiderProfile row instead of three fetches, two of them live. Everything here is display-only, so most values come from the JSON payload through the accessors on the model rather than from promoted columns -- the deep paths live there so there is one place to fix when zauth's shape moves. Deliberately NOT shown, because RiderProfile cannot supply them: * ZwiftPower rank -- zauth's ZpRider has no such column * best-ever rating -- needs a history table; this is an evictable snapshot * gender/country mismatch -- needs Zwift's raw values to disagree with vELO and vELO 2 each get a table: the rating, its mixed category and, for a woman, its women's category, now and at the 30- and 90-day peaks. Each peak carries the category zwiftracing gave it, never today's tier: labelling a 90-day-old rating with the current tier would be a lie rather than a gap, so a peak with no category of its own shows a dash. zwiftracing sends the women's categories for every rider; the velo_table and velo2_table filters keep that row to women, by the member's own gender and then zauth's. vELO 2 is a different scale from vELO (a rider might be 650 in vELO 2 and 1,600 in vELO 1), so it has its own section and is never set beside vELO as if comparable. {% endcomment %}
